L17 让「改动被正确落盘」可判定。这一节要回答下一句更危险的话：

**「我这版更好。」**

更好多少？对谁更好？花了多少钱换来的？弄坏了哪几个原本能过的题？——如果答不出这四个问题，你手里的百分比只是海报。

<Key>
这一节的中心论点：**L18 不是「怎么算一个成功率」，而是「怎么让一个差值有资格被相信」。**

每个数字背后都有一条不抛异常的路径把它变成假的：分母换了、任务坏了、答案就在沙箱里、方差没算、改动只是换了一批 bug、成本只平均了成功的、门禁语义写反了。分数是任务集版本、harness、资源、scaffold、重试策略、分母政策的函数——任何一项没写进结果，两个分数就不可比。
</Key>

L12 教的是通用评测卫生：kappa、bootstrap、`compareRuns` 的 fixed/broken 明细、先查评测可信再看分数。这一节把它落到 coding agent 上，并**修正 L12 里两处在这里不成立的做法**：二值小样本上的 bootstrap，和「弄坏 ≥3 就拦」这个常数。

## 一、任务集：fail-to-pass 是必要条件，不是充分条件

SWE-bench 把一个实例钉成四件事：仓库、commit、**修前必红**的测试（fail-to-pass，F2P）、**修完仍绿**的测试（pass-to-pass，P2P）。缺第一项，你测的就不是「修好了 bug」，而是「随便改点什么之后测试碰巧绿了」。

lab 的 `validateTaskSet` 把它变成 gaps：空 id、重复 id、缺 `failToPass`、`passToPass` 未定义、未钉 `repoPin`、某一难度 0 条。**gaps 非空时主指标作废**——它是 `codingGate` 的第一条 blocker。但这些只是结构检查。

### 1.1 F2P 只证明「gold 过、base 红」

直觉：有 F2P 和 P2P，任务就有效。

不是。F2P/P2P 是**从原 PR 的测试里机械抽出来的**，那些测试为验证某一次具体改动而写，会断言题面根本没提的字符串、类型、顺序。于是两个「人工验证过」的基准连续被拆：

| 基准 | 审计结论（OpenAI） |
|---|---|
| SWE-bench Verified（500 题） | 模型常失败的 138 题里，59.4% 的测试或题面有实质问题 |
| SWE-Bench Pro 公开集（731 题） | 约 30% 坏题（自动管线 27.4%，人工 34.1%）；OpenAI 于 2026-07-08 撤回了 L17 引用过的那条推荐 |

缺陷分四类：测试过严、题面欠规格、测试覆盖低、题面误导。**它们都不会让评测报错，只会让某些题永远红，或者让错的补丁变绿。**

### 1.2 有效性四件套

Anthropic 给每个任务写参考解，证明「可解、判定器配置正确」，并指出前沿模型上 **0% pass@100 最常见的原因是任务坏了**。参考解能过也排除不了「错的解被收」：UTBoost 给 SWE-bench 补测试，在 Lite 找出 23/300、Verified 找出 26/500 题测试不足，揭出 345 个原先被判通过的错误补丁。

所以一道题进集前至少过四道检查（运行要沙箱、不要模型；结果落盘后可零模型断言）：

1. base 上 F2P **每一次**都红
2. gold 上 F2P + P2P 全绿
3. **空补丁不通过**——否则这道题是空转的
4. gold 重跑 3 次结果一致

<Pitfall title="一个 flaky 的 P2P，就是一个假的「弄坏」">
SWE-bench 官方 issue #167 里，维护者说间歇失败的测试大多是 P2P。SWE-bench-Live 建集时每个实例验证 3 次，只留结果一致的，并建议分母用你机器上 gold 仍通过的实例数。

这直通第六节：flaky P2P 在 A/B 里表现为「候选弄坏了一道题」，门禁的 churn 规则会当真。
</Pitfall>

**lab 没有实现四件套**：`TaskInstance` 没有 `validity` 字段，`repoPin` 只查非空——demo 里甚至是 `demo/repo@e1` 这种拿任务 id 充当的 pin。

### 1.3 分层与污染

L12 说过分层抽样最重要的返回值是 `gaps`：「某一类一条都没有」不会以任何形式表现出来，一份只有 easy 的集会让任何改动都像胜利。lab 的难度是**手贴的**，更可靠的是用 gold diff 规模加结果历史来分。Anthropic 的另一条划分值得抄：**capability 套件**从低通过率起步，**regression 套件**应接近 100%，高通过率的题「毕业」进 regression，两套分开报。

污染分两类。直觉以为是「训练时见过」，但对 coding agent 更大的是**评测时泄漏**：答案就在沙箱里，agent 自己去拿。*SWE-Bench Pro Verified*（arXiv 2609.08149）审计 731 次基线运行，至少 103 题能在本地读到答案、49 题能走网络拿到——`git log/show` 恢复 gold、读沙箱文件、拉仓库、读 `instance_id` 里的 SHA。堵上之后：

```text
GLM-5.2    raw 78.80%   →   clean 57.32%   (−21.48pp)
配对转移    P→F 186 题       F→P 15 题        McNemar p < 0.001
```

训练期记忆基本不可审计，只能靠时间窗和私有任务；**评测期泄漏可以零模型地审、可以堵**：每题重建单 commit 仓库、id 不含 SHA、屏蔽代码托管域名、每次试验干净工作区。

题面也会泄漏。SWE-Bench+ 比对 SWE-Agent + GPT-4 的成功补丁：32.67% 的解法直接写在 issue 或评论里；过滤后 resolve rate 从 12.47% 掉到 3.97%。**你给自建集写题面时，最容易顺手把答案写进去。**

lab 用布尔位 `contaminated` 表达污染：`primaryTasks` 把它们拿出主指标，`codingGate` 看到它们被 resolve 只发警告。**污染样本留在集里当金丝雀**，比假装没有诚实；但布尔位分不出类别和通道，命令轨迹审计 lab 也没有。

<Key>
基准的半衰期不到一年：Verified 2026-02 被弃用；Pro 2026-02 被推荐、07 被撤回、09 被修补成 Pro Verified。

目标不是「选对基准」，而是**把选错的代价变小**：自有任务集当主指标，公开基准只作锚点，结果里记下基准版本、scaffold、预算。
</Key>

## 二、会说谎的成功率：口径、分母、尝试策略

### 2.1 同一批记录，四个口径

实验一用 `rateSpectrum` 并排算 `demoBaseline` 的 12 条 Attempt：

```text
口径          比率    命中/N    在数什么
apply         92%     11/12    patchApplied 且没有 error
f2p-only      58%     7/12     failToPassGreen，不管测试是否被改
naive+hacks   58%     7/12     failToPassGreen 或 hacked
resolve       50%     6/12     补丁落下、F2P 绿、P2P 绿、未改测试、无 block 级 hack
```

中间两行相同，因为 demo 里唯一的 hacked（m4）同时 F2P 绿——**四个口径在这份数据上只有三个值**。L17 的 `detectHacks` 在这里变成分类标签：block 级发现或 `testsMutated` 判 `hacked`，`warn` 级不阻止 resolved（CLS-6）。

<Key>
海报上的「成功率」没写口径，就按最宽松的那一行理解。主指标必须是 resolve，apply 只当诊断。

更好的表达是**漏斗**：提交 → 可应用 → F2P 绿 → P2P 未破 → 无 hack → resolved，每级是上一级的子集、分母统一。demo 上是 12 → 11 → 7 → 7 → 6 → 6。lab 没有 `funnel`，但能从命中数拼出来。
</Key>

### 2.2 分母是一个要声明的政策

直觉：分母就是题数。

看 lab 的分母：`applyRate` 的 n 是**全部** attempts（error 只从分子扣），`resolveRate` 的 n 是**去掉 error 后**的，f2p-only 和 naive 又是全部。demo 没有 error，看不出来。把两道 hard（h2、h3）标成沙箱崩溃再跑（本课实测）：

```text
            无 error        h2、h3 记为 error
apply       11/12  92%      10/12  83%
f2p-only     7/12  58%       7/12  58%
resolve      6/12  50%       6/10  60%    ← 严格口径反超了宽口径
```

**一个更严的指标，因为基础设施崩了两道难题，涨了 10 个百分点。** 没有任何一行报错。

<Pitfall title="infra error 偏偏更爱落在难题上">
难题跑得久、吃内存，更容易超时和 OOM，于是「去掉 error 再算」系统性地去掉难题。Anthropic 在 Terminal-Bench 2.0 上只改资源配置（6 种）：成功率相差 6pp（p 小于 0.01），infra 错误率从 5.8% 降到 0.5%。资源上限**是基准定义的一部分**。
</Pitfall>

分母至少有三种政策：`all`（error 记失败，默认、最保守）、`graded`（只算评分成功的，必须同时报 infra 错误率）、`errorRerun`（infra error 重跑到出结果，nightly 口径）。lab 的 `resolveRate` 实际上是 `graded`，`applyRate` 是 `all`——**同一张表里两种政策**。lab 没有政策参数；TODO 3 照参考实现写（verify 按它断言），但要知道它哪里不一致。

### 2.3 pass@k 在量你多开了几枪

pass@1 至少有三种定义：单次运行的比例、每题 n 次的 c/n 再平均、取每题第一次。SWE-agent 跑 6 次独立运行，resolve 均值 17.94 ± 0.49；同一配置的 pass@6 是 32.67%。aider polyglot 上 gpt-5(high) 的 `pass_rate_1` 是 52.0、`pass_rate_2` 是 88.0——后者是**拿到测试失败反馈后的第二次尝试**，榜单头条用的是它。

<Key>
`single`、`best-of-k`、`retry-with-feedback` 是**不同的系统**，不是同一系统的不同度量。成功率旁边必须带尝试策略标签。`pass^k`（k 次全过）少见于海报，正因如此才适合当你自己的稳定性指标。
</Key>

<Drill title="pass^k 为什么不等于 p̂^k，以及 lab 的 pass@k 偏在哪">

「单次 75%，3 次全过 ≈ 0.75³ ≈ 42%」假设**每道题成功概率相同**。真实任务是重尾的：若 SWE-agent 的各题同质，pass@6 应为 1 − (1 − 0.1794)⁶ ≈ 69.5%，实测 32.67%。反过来 pass^k 会比 p̂^k 高得多。

正确做法是每题跑 n 次、数成功 c 次，用 Codex 论文的无偏估计再对题平均：

```text
pass@k = 1 − C(n−c, k) / C(n, k)
pass^k = C(c, k) / C(n, k)

n=5, c=3, k=2   →   pass@2 = 0.9    pass^2 = 0.3
```

lab 的 `passAtK` / `passHatK` 取每题**前 k 次**（`slice(0, k)`），且只统计至少有 k 次的题：丢数据、依赖运行顺序、**分母随 k 变化**。例（本课实测）：t1「败成成」、t2 只有「成」、t3「成败成」——lab 给出 pass^2 = 0/2，无偏估计下 t1、t3 各是 1/3；分母从 3 掉到 2，因为 t2 只跑了一次。pass@k 不是 TODO（RATE-7/8/9 测参考实现），别把它的输出当无偏估计报。
</Drill>

## 三、N 小的时候：区间、配对、有效样本量

### 3.1 翻一题等于 ±10pp

实验二：N=10，从 8/10 翻成 9/10。

```text
版本           resolve   Wilson 95%
翻题前 8/10     80%      [0.49, 0.94]
翻题后 9/10     90%      [0.60, 0.98]
```

点估计 +10pp，区间几乎完全重叠；按成对算（1 题从败到成），差值的 bootstrap 区间也是 [0, 0.3]（本课实测）。切片让 N 更小：SWE-bench Multilingual 每种语言约 43 题，Wilson 区间各宽 27–30pp。

<Key>
先报区间，再报百分点。区间跨过对方是「看不出」，不是「赢了」。而「看不出」也不等于「没有」——可能只是题不够。
</Key>

<Drill title="比率用 Wilson，差值别用百分位 bootstrap">

L12 的 `bootstrapCI` 对连续分数没问题；对**二值、小 N、靠近边界**的结果会退化：0/30 时有放回地重抽永远得 0，区间是 [0, 0]，而 Wilson 上界还有 11.4%；27/30 时 bootstrap 给 [0.767, 1.000]，Wilson 给 [0.744, 0.965]。所以 lab 的 `RateReport.ci` 用 Wilson。

**差值**那一侧——`ablationTable.decisive` 和 `codingGate` 依赖的 `compareRuns.significant`——仍是百分位 bootstrap，而它在稀疏的不一致对上**反保守**。调研实测（N=40，弄坏 b=0）：

| 修好 c | bootstrap 判显著？ | 精确 McNemar 双侧 p |
|---|---|---|
| 3 | 否 | 0.250 |
| **4** | **是** | **0.125** |
| 6 | 是 | 0.031 |

b=0 时差值里只有 c 个 1。只要「重抽 N 次一个 1 都没抽到」的概率 `(1 − c/N)^N` 小于 2.5%，下界就大于 0——c≈4 就成立，**几乎与 N 无关**。精确检验要 c≥6。它是一个条件二项检验，只用乘除：

```text
p = min(1, 2 · Σ_{i ≤ min(b,c)} C(b+c, i) / 2^(b+c))
```

**这是 L12 → L18 要明说的修正**：二值、成对、小 N 用精确检验。lab 没有实现它，所以 claim 门在稀疏数据上偏乐观——本课实测，主任务集 11 题上 3 修 0 坏，`codingGate` 就给出了 `claimable = true`（成对 CI [0.091, 0.545]），而精确 p = 0.25。
</Drill>

### 3.2 成对为什么强，以及两类不确定性

两个版本跑的是**同一批题**。Anthropic 报告前沿模型的逐题得分相关在 0.3–0.7，配对差值的方差远小于两个独立比例之差；信息全在**不一致对**里。调研仿真（U 形每题成功率、真实 +5pp、N=200）：配对精确检验功效 21.3%，非配对 z 检验 6.9%——非配对**保守到几乎看不见效果**。

误差棒也分两种。SWE-rebench 榜首在调研抓取时是 64.5% ± 1.41%——这是**同一批题跑 5 次**的标准误；窗口只有 111 题，单凭「抽到这 111 题」，Wilson 95% 就是 [55.6, 73.1]。第三类是资源、版本带来的系统性偏差（Anthropic 那 6pp），不随 N 消失，只能固定下来写进键。

### 3.3 有效样本量：40 道题可能只有 6 个

同仓库的题共享夹具、配置、依赖，彼此相关。Anthropic 和 Miller 指出，在流行评测上**聚类标准误可以比朴素标准误大 3 倍以上**。

<Drill title="设计效应：一个式子算出你的集有多小">

统计学里的 Kish 设计效应：

```text
DEFF  = 1 + (m − 1) · ρ        m = 每个聚类的平均题数，ρ = 聚类内相关
N_eff = N / DEFF

40 题来自 2 个仓库（m = 20），ρ 只取 0.3：
DEFF  = 1 + 19 × 0.3 = 6.7      N_eff ≈ 6
```

**40 道题，有效样本量约 6。** 关于「跨仓库泛化」只有 2 个观测点。ρ 你不知道，但方向清楚：多收一个新仓库的题，比在同一仓库里多收几倍的题值钱。lab 的 `TaskInstance` 没有 `repo` 字段，这一段是理论。
</Drill>

### 3.4 先算你能看见多大的差

配对设计下，最小可检出效应（α=0.05、80% 功效）的正态近似是 `mde ≈ 2.8 · √(d / N)`，d 是不一致对占题数的比例。调研仿真里 d 约 25%，代进去：N=12（lab 的 demo）≈40pp，N=40 ≈22pp，N=300 ≈8pp。检出 +5pp 要 N≈785（正态近似）到 ≈1000（精确检验仿真）。

**个人集只能做「大效应」判断。** Anthropic 说 20–50 个来自真实失败的任务够起步，前提是早期效应量大。降 d 往往比加 N 便宜：每题跑 K 次，本来就会翻的题不再算进不一致对。比较数还会乘（7 指标 × 3 切片 × 6 消融 = 126 个），所以照搬 L12：只声明一个主指标，至多两个护栏。

## 四、成本：三个平均、一条读反了的曲线

### 4.1 最贵那一桶 resolve 最低，说明什么

实验三按 `costUsd` 把 demo 切成四桶：

```text
花费桶          n    resolve   均价
$0.01–0.02      3    100%      $0.02
$0.03–0.08      3     67%      $0.06
$0.09–0.40      3     33%      $0.20
≥$0.50          3      0%      $0.63
```

直觉读法：「越花钱越差」，或「最贵那桶是在 hard 上空转」。两种都缺证据。**成本是结果之后才确定的量**：失败的轨迹会继续重试、继续烧钱，「贵」部分是「失败」的后果；这张表回答不了「加预算有没有用」。

SWE-agent 的数据支持「失败更贵」：成功实例成本中位数 $1.21、12 步，未成功实例平均 $2.52、21 步。（「反向因果」是调研自己的框架，数据直接支持的只是这一点。）

<Key>
该画的是**预算截断曲线**：记下每条轨迹第一次 F2P+P2P 全绿时的累计花费 `costToGreen`，

```text
rate(B) = |resolved 且 costToGreen ≤ B| / N
```

它单调不降，能读出「再加钱买不到什么」。同一份 demo（把 resolved 的花费当 costToGreen）：rate($0.05) = 4/12，rate($0.10) = 6/12，**之后一直是 6/12**。
</Key>

lab 的 TODO 4 是 `costCurve`，不是预算曲线，`Attempt` 也没有 `costToGreenUsd`。把它当**观察工具**写；bench 里「最贵那一桶往往是 hard 上空转」的旁白，这张表没有证明。

### 4.2 「平均成本」有三个

SWE-agent 的 `$ Avg. Cost` 原文写明「averaged over all successfully resolved instances」——**只平均了成功的**。同一份 demo：

| 定义 | 算式 | demo |
|---|---|---|
| 只算成功的 | 成功的花费 / 成功数 | $0.042 |
| 每次尝试 | 总花费 / 尝试数 | $0.227 |
| 每个 resolve | 总花费（含失败）/ 成功数 | $0.453 |

**同一批数据，三个「平均成本」差 10.9 倍。** lab 的 `efficiency` 给第二个（`meanCost`）和第三个的倒数（`resolvesPerDollar`）。

### 4.3 合成一个「性价比」也会骗人

直觉：resolve / 美元，一个数就够了。拿 lab 自己的三份记录算 `efficiency`（本课实测）：

```text
                               resolve   均价      resolves/$
full（基线）                     50%      $0.227    2.21
no-verify（实验四的消融）         33%      $0.150    2.22   ← 质量掉 17pp，比值略升
候选（实验五，弄坏 3 个 easy）    50%      $0.103    4.84   ← 翻了一倍多
```

分子和分母一起跌，比值把质量下跌抵消了。**成本必须作为护栏和主指标并列，不能合成一个比值**——尤其当改动的机制就是「更早停下」时。

美元是 tokens × 价格表 × 缓存命中，三者都会动：存 token 分项，展示时重算；多配置比较画**帕累托前沿**——aider 榜单上 o3-pro(high) 84.9% / $146.32 被 gpt-5(high) 88.0% / $29.08 全面支配。lab 没有实现这些。

## 五、消融：只留会改决策的旋钮

### 5.1 跑之前先问四个问题

1. **结果会改变我哪个决定？** 答不出来就不跑
2. **被消融的东西在轨迹里用到了吗？** 从没被调用的工具，消融它是空操作
3. **我能检出多大的差？** mde 比「值得改决定的最小差」还大，就先加 N 或降噪
4. **它和别的因素有交互吗？** 有，就要因子设计

改显示名、重排 `tools` 数组——过不了第一问。该消融的是 L17 钉住的决策面：

| 消融 | 假设 | 会改的决定 |
|---|---|---|
| 拿掉 verify-before-stop（`canStop`） | hack 升，clean resolve 降，成本降 | 是否保留强制验证 |
| 拿掉 plan 阶段 | 小题无益、多文件题有益 | 小题是否跳过 plan |
| 拿掉 `NOT_UNIQUE` 的分级反馈 | 恢复变差，步数上升 | 是否保留复杂反馈 |
| 换模型 | 整捆变化，含作弊倾向 | 选型；须在反泄漏环境做 |

调研没有找到 plan 阶段的公开消融数据——你能自己产出证据，但它效应小、和题型交互强，你的集很可能检不出。**「检不出」本身就是结论的一部分。**

### 5.2 真正改决策的旋钮，在 N=12 上也不 decisive

实验四把 demo 的 medium 题改成「改测试假绿」、花费打折，模拟拿掉 verify-before-stop：

```text
配置          resolve   Δ        decisive
full          50%       +0pp     yes
no-verify     33%       −17pp    no
```

**第一，消融表必须和主口径绑定。** 同一批记录换成 f2p-only：full 58%，no-verify 67%，均价还从 $0.227 降到 $0.150——宽口径会奖励错误行为。

**第二，`decisive = no`。** N=12 上只翻了 2 题（m1、m3；m4 在基线里已是 hacked）。成对差值是两个 −1 加十个 0，bootstrap 区间 [−0.417, 0]：重抽 12 次一个 −1 都抽不到的概率是 (10/12)¹² ≈ 11%，远大于 2.5%。

<Key>
「去掉 X 没掉分」或「掉了但不显著」不等于「X 没用」。还有三种解释：**功效不足**（调研仿真里 N=300、真实 +5pp 时功效只有 30.7%）、**补偿**、**天花板**。

消融结果报三样：delta、区间、mde。delta 的绝对值小于 mde 时，只能写「无法检出 ≥mde 的影响」。
</Key>

SWE-agent 在 Lite 上的界面消融（N=300、**单次运行**，基线 18.0%）：没有编辑工具 10.3%，没有搜索工具 15.7%，没有 demo 16.3%。两次独立运行之差的标准误约 3.1pp，后两行**不能下结论**。

### 5.3 `ablationTable` 量的是什么

组件有交互时，从全配置往下减和从空配置往上加，结论可以相反。lab 不做因子设计，一次改一个，对每个配置算：

- `deltaVsBaseline`：两边 `resolveRate` 之差（分母各自去掉 error）
- `decisive`：按**位置**配对的差值（error 记 0）的 bootstrap 区间是否完全在 0 一侧
- `ci`：**该配置自己 resolve 率的 Wilson 区间**，不是差值的区间——名字容易误导

有 error 时前两项分母不同，量的不是同一件事。TODO 5 照参考实现：调用方保证同一任务顺序；baseline 行 `decisive` 恒为 true；缺 baseline 抛错（ABL-4）；最后按码点排序（见第七节的 PyMirror）。

## 六、成对对比：先看 onlyA / onlyB，再看净值

### 6.1 每个海报指标都说「更好」

实验五的候选版本，在主任务集（去掉污染的 c-easy，11 题）上和基线比：

```text
               基线          候选
apply          10/11  91%    11/11 100%
f2p-only        6/11  55%     8/11  73%
resolve         5/11  45%     5/11  45%
resolves/$      2.21          4.84         （全部 12 条，本课实测）
```

apply 涨了，f2p-only 涨 18pp，「性价比」翻倍，非成对 Δresolve = 0。成对明细：

```text
onlyA（基线过、候选不过）   e1, e2, e3     ← 弄坏三个 easy
onlyB（候选过、基线不过）   m2, m4, h4
neither                    h1, h2, h3     ← 候选改测试「过」，被判 hacked
both                       m1, m3
```

h1–h3 的 F2P 绿了，但改过测试，被判 `hacked`，所以不在 onlyB 里——宽口径下它们是三个胜利。`codingGate` 给出两条 BLOCK：「候选有 3 次 hacked/testsMutated」「弄坏 3 个已通过任务」。

<Key>
非成对均值差可以是 0，同时你弄坏了三个 easy、换来另外三道题，还多了三次改测试的「通过」。

**成对明细比 Δ 先被阅读。** 这是 L12 的 churn-first 顺序：弄坏三个是确定发生了的事，不需要统计检验确认。
</Key>

`pairedAB` 每题只取**第一次** attempt；两边 id 不一致时**静默只比交集**，样本集被换要由 `codingGate` 单独查（GATE-4）。

### 6.2 A/A：同一个配置跑两次，也会「弄坏」几道题

直觉：同一配置跑两遍，onlyA 和 onlyB 都该是空的。

agent 是随机的，temperature=0 也一样。调研在 U 形每题成功率下估计 **A/A 的不一致对约占题数的 25%**（U 形是建模选择，真实分布未知）。N=40 的 A/A 里出现 4 修 + 4 坏是常态，`compareRuns` 会对它打出「这是换了一批 bug」。

「弄坏 ≥3 就拦」是写死的常数。调研的模拟里，这一条在 **A/A** 下的拦截率 N=30 时 0.73、N=100 时 1.00——**几乎总是拦**。它在当前 lab 里原样保留，两种 mode 都生效。

阈值要由噪声底校准：先跑 A/A，阈值取 churn 分布的 1−α 分位，或对「弄坏 vs 修好」做精确符号检验。lab 没有实现；demo 的 `broken = 3` 是**刻意构造**的坏候选，常数恰好够用。搬到自己的集上之前，先跑一次 A/A。

### 6.3 协议，以及什么时候不该 A/B

- **按题交错**（A1 B1 A2 B2），别整批先 A 后 B——服务商静默变更、限流、缓存冷热会落到某一臂
- **每次试验全新工作区**：Anthropic 发现 Claude 翻看过之前试验留下的 git 历史
- **缓存键包含输入**：SWE-bench 官方 harness 按 `run_id` + `instance_id` 缓存，补丁变了也复用旧结果
- **每题 K≥2**；运行键只允许在被测因素上不同

`l18/runner.ts` 不做这些，它只演示一条运行怎么落成 `Attempt`（测试没真跑，`failToPassGreen` 写死为 false）。

也不是每个改动都该 A/B：确定性语义（`applyEdits`、diff 解析）写单测；只改成本的（缓存断点、压缩）用已落盘轨迹**回放**重算 tokens；预期效应小于 mde 的，做机制级 micro-eval 或承认检不出；用户体验留给线上实验（L19）。**只有预期效应大于 mde 的改动，才值得一次配对 A/B。**

## 七、回归门禁：regress 与 claim

### 7.1 门禁的顺序

`codingGate` 的顺序和 L12 一样：**先查评测可信，再看分数。**

```text
1  validateTaskSet 有 gap                   → BLOCK「任务集不可用」
2  污染样本上出现 resolve                    → 警告
   ── 以下只看 primaryTasks ──
3  候选缺少 / 多出任务                        → BLOCK「样本集被换过」
4  候选里有 hacked                           → BLOCK
5  onlyA ≥ 3                                 → BLOCK「换了一批 bug」
6  成对 CI 完全在 0 以下                      → BLOCK，两种 mode 都拦
7  点估计上升但不显著      claim   → BLOCK「不可宣称更好」
                           regress → 警告「若要写更好请改用 claim」
8  apply↑ 而 resolve 未↑                      → 警告
```

`claimable` 只在 claim 模式、没有 blocker、且成对 CI 下界大于 0 时为 true。

### 7.2 为什么必须是两扇门

直觉：显著更好才能合并。

lab 的旧版草稿就这么写：「点估计上升但不显著 → blocker」。调研模拟 N=100 时这一条的拦截率：真实效应 0（A/A）时 49%，−5pp 时 17%，−10pp 时 3%。**越差的版本越不会被拦**——它随机拦掉一半 A/A 的 PR，同时放过真实退化。

两个零假设被混成了一个。**regress**（默认，每个 PR、每晚）问的是能不能说明没变差——非劣；**claim** 问的是能不能宣称更好——优效，只在写下「更好」两个字之前用。

verify 用同一份数据测这件事（GATE-3 / 3b / 6 / 6b）：清掉基线里 m4 的改测试、再修好 h1。主任务集上 resolve 从 5/11 到 7/11——**点估计 +18pp**，成对 CI [0, 0.455]。regress 放行并警告；claim 拦下，`claimable = false`。+18pp 在 N=11 上不显著，这本身就是第三节的结论。

### 7.3 lab 的门禁还没管的事

调研给出的完整语义里，这几条 **lab 都没有实现**：infra 错误率超限应判「无法评分」而不是「变差了」；任务内容哈希要进键（id 没变、测试改了，GATE-4 抓不到）；基线的 hack 也要查；基线应是每题的 (c, n) 分布而不是一个点。

nightly 每晚判一次、α=0.05，平均每 20 晚误拦一次 A/A。常见做法是更严的 α 加「连续两晚确认」（调研列为标准做法，未给文献）。

### 7.4 CI 里不能有模型

把基准放进 PR 门禁只会得到**随机红灯**。能零模型断言的是**评测系统本身**：任务集完整性（SET）、判定器（CLS）、统计器（RATE、COST、ABL）、门禁语义（AB、GATE）、夹具自洽（FIX）、双语言格式化（FMT），合计 56 条，TS 和 Python 同数。判定器最值得测：UTBoost 修正测试输出解析器后，Lite 40.9%、Verified 24.4% 的榜单名次变了。

<Pitfall title="全绿不等于你的 TODO 是对的">
这一节初稿的 verify 有几条**怎么写都会过**的断言：

- **GATE-5** 写的是「警告里有 apply，或者 gate4 没通过」。gate4 那份候选本来就会因为弄坏 5 题被拦——忘了写 apply 警告，这条照样过
- **COST-3 / COST-4** 是「首桶下界 ≤ 末桶下界」「末桶均价 ≥ 首桶均价」，对排好序再切的桶构造性成立；**ABL-3** 的 baseline Δ=0 恒真
- 只有 `claimable = false` 的断言，没有 `true` 的。把它写死成 `false` 也全绿

现在它们换成了有牙的版本：GATE-5 的候选只多 apply、不弄坏也不 hack，门禁必须**放行并警告**；COST-3/4 钉住每桶的下界、条数和 resolve 数（`[3, 2, 1, 0]`），另加 error 不进桶（COST-6）和末桶吃余数（COST-7）；ABL-3 钉住 Δ = −2/12 且不 decisive，ABL-5 钉住码点序；GATE-7 补上「显著更好 → claimable」的正例。

还剩两类：

- **GATE-2 / 3b / 4 / 6** 用 `includes` 匹配文案——措辞不对会红，某些逻辑不对反而能绿
- **GATE-6b** 在一份本来就不显著的数据上查 `claimable = false`。`claimable` 漏掉 `pass` 或 `ci.lo > 0`，这条照样绿；GATE-7 是正例，也抓不到这种放宽。污染警告则没有断言去查

测验里那道 debug 题就是这两类的标本。门禁这种方向容易写反的代码，自己再造一份 A/A 数据过一遍。

判断一条断言有没有牙，问一句：**我能不能写出一个错的实现让它通过**？能，它就只是在测你会不会抄文案。
</Pitfall>

<PyMirror>

bench 和 verify 要求 TS 与 Python 逐字节一致。评测代码里至少三处会断。

**舍入。** `toFixed` 在精确平局上远离零，Python 格式化取偶：`0.0625` 保留 3 位，TS 是 `0.063`、Python 是 `0.062`；`2.5` 取整是 `3` 对 `2`。L19 的 lab 就因 `0.063` / `0.062` 出过一次分歧。L18 初稿有两处同样的写法：bench 的 `pct()`，和 `codingGate` blocker 里的成对 CI（`toFixed(3)` 对 `:.3f`）。当时一致只因 demo 的 N 是 11 和 12；主任务集换成 40 题，1 题命中就是 2.5%，两边会分别印 3% 和 2%。

现在两处都走 `fmtFixed` / `fmt_fixed`。TS 侧就是 `toFixed`，只把 `-0` 归成 `0`；Python 侧用 `Decimal(x)` 取 float 的精确值，再 `ROUND_HALF_UP` 量化——在 decimal 里这个模式的意思正是「平局远离零」，逐字节复现 `toFixed`。`FMT-1` 钉住几个平局；本课对两边跑了四万多个输入（含全部 k/16、k/8 平局和负零），零分歧。

**顺序。** `localeCompare` 按语言习惯排，Python 的 `sorted` 按码点：`['B','a','_x','1']` 在 JS 里排成 `_x 1 a B`，在 Python 里是 `1 B _x a`。所以 `ablationTable` 用显式的 `cmpCodePoint`（`ABL-5`）。另一处是后来修的：Python 侧 `coding_gate` 原先用一个 `set` 遍历生成「候选缺少任务」，而字符串 hash 默认每个进程随机化，缺多道题时 blocker 顺序在两次运行之间都可能不同。现在用 `dict.fromkeys` 保插入顺序，对齐 TS 的 `Set`。

**libm。** `log` / `exp` / `pow` 在 V8 和 CPython 之间约 5–10% 的输入末位不同，`sqrt` 为 0（调研实测）。统计代码只用加减乘除和 `sqrt`。
</PyMirror>

## 九、这节课的收尾

五句该记住的话：

1. **F2P 是必要条件，不是充分条件。** 坏题、泄漏、flaky 都不报错
2. **分母和尝试策略是政策，要写出来。**
3. **N 小时先算 mde。** 二值小样本用 Wilson 和精确检验
4. **成本是结果的后果。** 不要合成性价比比值
5. **成对明细先于净值；regress 测非劣，claim 测优效。**

给 L12：churn-first、先查评测可信再看分、事前声明主指标——原样保留；二值小样本上的 bootstrap、「弄坏 ≥3」的常数——在这里被修正。判定器从 judge 变成了**测试和测试输出解析器**。

给 L17：`detectHacks` 变成 `hacked` 标签和 raw / clean 两个数；`canStop` 变成第一个值得消融的旋钮。

给 L18x（深度选修）：如果评测之后要改的是模型本身而不只是 prompt，这一节的口径就是奖励。resolve 的定义、`hacked` 标签、pass@k 都会原样进去，只是它们从「报数」变成了「塑造行为」。

给 L19：这一节证明「这版更好」，并说得出证据有多硬；下一节把它挂到队列、配额和别人能打开的入口上。接过去之前要定三样 lab 里还没有的东西：nightly 退出码（通过 / 回归 / 无法评分）、基线文件形状、线上指标口径。
