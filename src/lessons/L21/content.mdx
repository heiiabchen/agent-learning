## 一、地图的形状：节点是不变量，边有 kind

### 1.1 节点为什么不能是产品名

试着把这门课里的三句话写成节点：

| 写法 | 能活多久 |
|---|---|
| 「主力模型是 `deepseek-chat`」 | 2026 年 7 月退役那天作废 |
| 「Cursor 默认每次都问」 | 3.5（2026-05-22）弃用 "Ask Every Time" 那天作废 |
| 「多处匹配零写入，逼模型扩大上下文」 | 只要你的编辑工具还带唯一性检查，就成立 |

前两行是**事实**，回答「现在是什么」，天生带保质期。第三行是**不变量**，回答「违反了会坏在哪」，保质期取决于机制，不取决于厂商。

lab 的 `ConceptNode` 里承重的是两个字段：`invariant`（一句话）和 `evidenceAt`（证据最后核实的 Unix ms，0 = 未知）。**没有第二个字段的笔记，不知道自己什么时候该被怀疑。**

### 1.2 四种边

| kind | 读法 | 骨架图里的例子 |
|---|---|---|
| `requires` | A 需要先理解 B | `edit.can_stop` → `edit.not_unique`（「先能改对再谈终止」） |
| `contrasts` | A 与 B 是易混对 | `ops.idempotency` ↔ `edit.not_unique`（「都在防双份」） |
| `measured_by` | A 的对错由 B 度量 | `eval.resolve` → `edit.not_unique` |
| `iou` | A 给 B 留下欠条 | `ui.can_execute` → `ops.checkpoint`（「审批记忆在 L19 兑付」） |

`courseGraph()` 有 10 个节点、10 条边：6 条 `requires`、2 条 `contrasts`、1 条 `measured_by`、1 条 `iou`。节点来自 L12、L15–L19——**L13 和 L14 一个都没有**，这是你往上挂东西的第一个地方。

`requires` 是「`from` 需要 `to`」。顺着走（`prerequisites`）是补课：实验一找到 `eval.gate → eval.resolve → edit.can_stop → edit.not_unique`，门禁看不懂就沿这条链往下补。逆着走（`dependents`）是波及，即 `blastRadius` 的方向。

<Pitfall title="lab 的算法只认 requires">

`prerequisites`、`dependents`、`blastRadius`、`shortestRequiresPath` **全部只沿 `requires` 走**，另外三种 kind 只是标注。所以 `ops.checkpoint` 到 `edit.not_unique` 是 `null`（只隔一条 `contrasts`），`ui.can_execute` 到 `ops.checkpoint` 也是 `null`（那条是 `iou`）。

**一条 `iou` 边在 lab 里不会让任何东西报警**——欠条兑没兑，只能你自己追。
</Pitfall>

## 二、欠条：iou 边在这门课里是怎么兑付的

这门课一直在用一种写法：某节说「这个以后讲」，后面某节写「给 Lxx 的兑付」。摊开：

| 「你在 L16 会发现自己有别人没有的优势」 | L00 | L16 | 习惯了「内容正在到达、随时会变、屏幕必须自洽」 |

**第二，「兑了」要分清兑的是什么。** 很多欠条兑的是方法，不是实现：

- **TTFT 基线**：L19 拆成 `queue_wait` / `start_latency` / `model_ttft` 三段，但 lab 没有计算函数，第三段只有真实调用才有。方法兑了，数字仍是你的。

- **续跑前的工作区哈希校验**：L19 写的是「`resumeCheck` 是你要补的那一刀」。
- **L15 自己列的三张**：延迟、批处理与缓存的叠加、`temperature` 会不会打掉缓存——后面的课没有再接。

| 榜单快照 | aider 榜单（2025-08-23 的 88.0%）、swe-rebench（2026-09 抓取的窗口） | L18 调研 M-6 |

**几乎每一行过期时都不报错。** `deepseek-chat` 至少会报 model not found；其余几行连这个都没有。

<Note title="不要相信任何教程里写死的模型 ID，包括这一份">

这是 `labs/README.md` 的原话。对策是 `pnpm models`（或 `uv run python -m shared.models`）：问 API 当前有哪些模型，把要用的填进 `.env`。**模型 ID 是配置，不是常量。**
</Note>

### 3.2 一条证据在这门课里过期的全过程

1. L17 的调研（2026-09-29）引用 OpenAI 2026-02-23 的原文「We recommend SWE-bench Pro.」，标 `[P]`。
2. 十天后，L18 的调研（2026-10-09）把它列为更新项：OpenAI 在 2026-07-08 已撤回对 Pro 的推荐，估计约 30% 坏题，且不推荐替代品。
3. 结论随之改成：**讲稿不再推荐任何「当前最好的公开基准」**，只讲如何不依赖单一基准的存活。

调研写于 9 月底，引的是 2 月的原文，而推荐 7 月就撤了。**读到原文 ≠ 原文仍是作者现在的立场。** 所以 `evidenceAt` 不是来源发布的日子，也不是你读到它的日子，**是你最后一次确认它仍成立的日子。**

第二例更小。L16 引的 OpenTelemetry 指标名 `gen_ai.server.time_to_first_token`（调研 2026-09-15 访问，`[P]`），三周多后 L19 的调研再抓时页面已迁移，于是**不写指标名，只讲三段拆分**。这没证明名字错了，只说明**名字类证据的保质期，可以比写一份讲义还短。**

### 3.3 过期慢的：机制与算术

| 不变量 | 为什么慢 | 课 |
|---|---|---|
| 标准队列是 at-least-once；「只执行一次」靠你自己造 | 投递语义 | L19 |
| 多处匹配零写入（`NOT_UNIQUE`） | 你自己工具的语义 | L17 |
| resolve ≠ apply；改测试 = hacked | 定义 | L18 |
| 缓存命中是前缀哈希相等 | 前缀缓存的机制 | L15 |
| `/repo` 不覆盖 `/repo-evil` | 字符串算术 | L17、L19 |

同一句话里经常两种都有。L15 的「读取 0.1 倍、写入 1.25 倍」是价格，快过期；「一次性前缀开缓存是亏的」是从价格推出的结构，只要写入比普通输入贵就成立。**结构进 `invariant`，数字进证据，带日期。**

<Key>
判断过期快慢，先问：**它是名字或数字，还是机制或算术？** 前者带日期，后者带断言。让一条知识过期变慢，最便宜的办法是把它写进你自己的 verify。
</Key>

### 3.4 「查不到」也是证据，也会过期

调研文件里的「查不到一手来源」不是废料，是地图上的负空间：

- 流式输出提升满意度：没有任何厂商公开过 A/B 数据（L16 调研 NF-5）
- Devin 的「13.86%」：对应哪个子集、是否 pass@1 无法确认，不得引用（L17 调研 N-4）
- 「AWS ALB 会缓冲响应」：官方属性文档里没有这个开关（L16 调研 NF-9）——不是未证实，是**与一手文档不符**

两条纪律。**「查不到」也要记日期**：「没有 plan 阶段的公开消融数据」是否定性断言（L18 调研 N-6），明天有人发一篇就不成立了。**「查不到」和「错」分开记**：前者等新证据，后者要主动纠正。

## 四、信息源：标签和权重是两根轴

### 4.1 五个标签

研究文件给每一句话打标签（据 L19 调研头部）：

| 标签 | 含义 |
|---|---|
| `[P]` | 一手：官方文档 / 官方博客 / 规范 / 论文，本轮已读原文或原文摘录 |
| `[P2]` | 近一手：一手但只读到摘要，或二手转述一手 |
| `[S]` | 记忆 / 惯例，**未复核**，全部列入未溯源清单 |
| `[L]` | 本地仓库事实（读过代码 / 文档） |
| `[O]` | 自产证据：自己跑过的探针，方法与数字可复现 |

直接拿来当笔记模板。关键在 `[S]`：**它不能单独支撑任何数字**，要进单独的清单等你复核或删掉。加上 3.2 的教训，一条笔记至少是「标签 + 核实日期 + 一句话」：

```text
[P]  2026-09-29  OpenAI 推荐 SWE-bench Pro          ← 读的是一手
[P]  2026-10-09  同一家 2026-07-08 撤回该推荐        ← 一手被一手更新
[O]  2026-10-09  verify：bob 用 alice 的 key 拿不到作业  ← 自产，可重跑
[S]  ——          「某产品内部是这样路由的」            ← 不进任何结论
```

lab 的 `Source` 只有 `kind`、`trust`、`reproducible`，**不实现这套标签**。两者问的不是一件事：标签问「你怎么拿到这句话的」，`sourceWeight` 问「作者有没有理由说得好听一点、能不能复核」。厂商博客可以是 `[P]`，在 `sourceWeight` 里仍压在 0.6 以下。lab 也不区分断言类型：厂商说「我们停用了某基准」是陈述自己的行为，说「我们的模型提升了 X%」是对外宣称——**你的笔记要分开。**

### 4.2 sourceWeight 的精确规则

```ts
let t = s.trust
if (s.kind === 'own_verify') t = Math.max(t, 0.9)   // 地板
if (s.kind === 'twitter') t = Math.min(t, 0.2)      // 天花板
if (s.kind === 'vendor_blog') t = Math.min(t, 0.6)  // 天花板
if (s.reproducible) t = Math.min(1, t + 0.1)        // 可复核加成
if (!s.reproducible && s.kind === 'paper') t = Math.min(t, 0.7)
return Math.round(t * 1000) / 1000
```

实验四：可复核的 own（trust 0.5）→ 1.000；可复核的 paper（0.8）→ 0.900；不可复核的 blog（0.8）→ 0.600；不可复核的 twitter（0.9）→ 0.200。实验没展示的三件事：

- **天花板在加成之前。** 可复核的厂商博客能到 0.7，可复核的 twitter 能到 0.3；verify 只测了不可复核的情况。
- **`official_doc` 没有地板也没有天花板**，trust 原样，可复核再加 0.1。
- **不可复核的论文压到 0.7**：trust 0.95 却不给代码数据，和可复核、trust 0.6 的论文同分。

`own_verify` 的地板奖励的是「可重跑」，不是「测对了东西」。L18 调研审计过一版草稿：verify 45/45 全绿，同时门禁把「点估计上升但不显著」当成拦截条件——非劣和优效混成了一门。

### 4.3 引用纪律：决策不依赖百分比

L17 调研写给课件作者的引用纪律里，最重的一条：

> 本节的所有工程决策都必须能只靠「机制 + 不对称成本」论证，不依赖任何百分比。

范例是模糊匹配：会导致静默错改，机制上有源码证据；**多常发生，没有任何一手来源测过**（L17 调研 M-6）。决策依据是检测只需一次字符串计数，发生率再低也值得防。**这是基于不对称成本的决策，不是基于测量的决策。** 把这句写进节点的 note，下一节它会救你一次。

## 五、新论文三问（30 分钟版）

1. **它声称推翻哪条边？** 与你的 invariant 无关，进「待观察」桶。
2. **分母是什么？** resolve 还是 apply？有没有 fail-to-pass？pass@1 还是 pass@k？N 多大？
3. **能不能零模型复现关键句？** 能 → 写进 lab，来源变成你的 `own_verify`；不能 → 最多加一条低 trust 注记。

第四步是采纳的代价：**跑一次 `blastRadius`。** 写不完就先别改主指标。

### 5.1 例一：榜单上的「X% resolved」

**推翻哪条边？** 它碰 `eval.resolve` 和 `eval.gate`，但推翻不了任何东西——它是个水平值。承载决策的是配对差值、它的不确定性和成本。

**分母？** 同一批尝试有四种口径。改测试骗绿算不算？头条是第几次尝试（aider 的头条是带测试错误输出的 `pass_rate_2`）？scaffold 的 commit hash 写了吗？基准本身还活着吗？N=10 时翻一题就是 ±10pp。

**零模型复现？** 模型那次运行复现不了，但**判定**可以：把公开的轨迹落成 `Attempt`，跑 `classifyAttempt` / `rateSpectrum`。不公开轨迹就是「不能」。结论：待观察桶。

**对照一篇能过三问的。** L18 调研引用的 *SWE-Bench Pro Verified*（arXiv 2609.08149，`[P]`）：731 题重建为单 commit 仓库、屏蔽代码托管域名后，GLM-5.2 从 78.80% 掉到 57.32%，186 题由过转挂、15 题由挂转过。**同一批题、成对报告、先给明细再给净值**——正是 L18 教的形状。它加固「先查评测可信，再看分数」，不推翻什么。

### 5.2 例二：「开缓存省 90%」

**90% 是什么？** 读取 0.1 倍的单价折扣，只作用在**命中的那部分前缀**上。

**分母？** 复用次数。L15 实验一：N=1 是 1.25 倍，**亏 25%**；N=10 省 78.5%。只读 `input_tokens` 的监控，还会把官方那个 200k 命中的例子显示成降了 99.97%。

**前提？** 前缀低于门槛不报错、直接不缓存；DeepSeek 兼容表里 `cache_control` 四次写着 `Ignored`；路由每切一次模型，整段前缀重写一遍。

**零模型复现？** 能。L15 实验一的倍率列和 OpenAI 原文的 1.35× / 2.15× 对得上——这一步做完，它就从 `vendor_blog` 变成了 `own_verify`。命中看 `usage`，不看 TTFT：这正是 `budget.usage` 节点的不变量。

<Drill title="例三：一篇不碰任何边的论文">

假设你读到一篇论文，测出「模糊匹配的静默错改率很低」。同事据此提议：换成首命中 + 模糊匹配，去掉 `NOT_UNIQUE`。

**推翻哪条边？** `edit.not_unique` 的依据（4.3）是不对称成本，不是发生率。低发生率**不改变检测只需一次字符串计数**这件事。它填的是 L17 调研里一个「查不到」的空，不是你图上的一条边。

**采纳的代价？** `blastRadius(g, 'edit.not_unique')` 有 4 个节点，横跨 L17 和 L18。L18 的消融表里本来就有「拿掉 `NOT_UNIQUE` 的分级反馈」这一行——真想知道，在自己的任务集上跑它。

结论：待观察桶。救你的是 note 里那句「基于不对称成本」。
</Drill>

## 六、技术判断力：换工具之前的三问

论文三问读别人的断言。换新工具、新模型、新 harness 之前，还有三问：

1. **失败时有没有信号？** 前缀太短、`cache_control` 被丢、fast mode 降速，都不报错——但最后一个有 `usage.speed` 可读回。有读回字段，就写一个每次都读它的判定器；没有，就不进主路径。
2. **数字的口径写死了吗？** 同一个 `input_tokens`，Anthropic 不含缓存部分，OpenAI 已包含。
3. **有没有一条能放进 CI 的断言？** CI 只信任零模型的 verify；真跑模型的 runner 不进 CI。

三问都「无」→ 可以玩，不要进主路径。

<Pitfall title="把排行榜截图钉进地图当证据">
榜会刷、集有洞、harness 会偏。榜面分数可以当「谁值得一看」的线索，不能当边的 `evidenceAt`——L18 调研管 Verified → Pro → Pro Verified 这一串叫「基准有半衰期」。
</Pitfall>

## 七、过期与影响面：findStale × blastRadius

### 7.1 findStale 的精确语义

- 判据：`now - evidenceAt > maxAgeDays * 86_400_000`，**严格大于**；`ageDays` 向下取整
- `evidenceAt === 0` → `ageDays` 是 `Infinity`，**不管窗口多大都报**（STALE-3）
- 每条带上该节点的 `blast`；按 id 码点序排，不是按紧急程度
- 它**不删任何东西**

实验三，时钟 2026-10-09、窗口 60 天：

```text
节点                  账龄(天)  波及
budget.usage          69        0
eval.kappa            100       1
```

`eval.kappa` 的证据最老，并且有一个依赖者 `eval.gate`。`budget.usage` 没有任何节点 `requires` 它，所以波及是 0。

**过期 ≠ 错误。** L12 的「原始一致率可为零信息」是算术，100 天不会让它变假。过期的意思是：**叙事还在用它，而你已经 100 天没确认过它。**

<PyMirror>

Python 侧未知证据的 `age_days` 是 `math.inf`。两边最容易对不上的是**月份**：TS 的 `Date.UTC(2026, 6, 1)` 和 Python 的 `_utc_ms(2026, 7, 1)` 是同一天——前者月份从 0 起，后者 1–12。
</PyMirror>

### 7.2 blastRadius：一次作废要重核哪几课

`blastRadius` 从起点沿 `requires` 逆向 BFS，去重、排序、**不含自身**。实验二：若 NOT_UNIQUE 的证据作废——

| 被波及的节点 | 课 | 要重核的那句话 |
|---|---|---|
| `edit.can_stop` | L17 | verify 必须在最后一次 edit 之后 |
| `sandbox.prefix` | L17 | 路径不是 `startsWith`，`ws-evil` 必须挡住 |
| `eval.resolve` | L18 | 主指标不是 apply；改测试 = hacked |
| `eval.gate` | L18 | 非劣与优效分两门 |

不在影响面里的也值得看：`ops.idempotency`（L19）和 NOT_UNIQUE「都在防双份」，但只连着一条 `contrasts`，lab 不会提醒你。`eval.resolve` 在影响面里，是因为 `requires` 链经过 `edit.can_stop`，不是因为那条 `measured_by`。

另一例：`blastRadius(g, 'eval.kappa')` 是 `[eval.gate]`——重读 L12 的 kappa，顺手核 L18 门禁的顺序。

<Key>
**blastRadius 只沿你画出来的 `requires` 走。** 「这个错了那个也得重看」的依赖要画成 `requires`；画成 `contrasts` 的，只能靠你记得。
</Key>

### 7.3 窗口选多大

同一个 2026-10-09：窗口 7 天报出全部 10 个（10 月 1 日核实的也已 8 天），30 天报 3 个，60 天报 2 个；时钟拨到 2027-01-09、窗口 90 天，又是全部 10 个。

窗口太短，**全报等于不报**。lab 对所有节点用同一个窗口，`ConceptNode` 没有保质期字段——名字类和机制类该用不同窗口，这是你扩展时最值得加的字段。

## 八、维护节奏：周、月、季

| 节奏 | 做什么 | 用到的 |
|---|---|---|
| 每次事件 | 厂商公告、模型退役、线上故障 → 找到节点，看 blast | `blastRadius` |
| 每周 | 本周的失败和论文过三问，进图或进待观察桶 | 三问 |
| 每月 | `pnpm models`；窗口 30 天；重核名字、数字、默认值 | `findStale` |
| 每季度 | 窗口 90 天；重跑所有 `own_verify`；清点 open 欠条 | 两者 |

报告出来之后，**按 blast 大小排优先级**，不要按 lab 的 id 序：`edit.not_unique` 波及 4 个，比 `eval.kappa` 先核。重核完一个节点，才更新 `evidenceAt`——没读就改时间戳，等于把告警静音。

证据也不只来自论文。L19 留给这一节的话是：上线之后，死信深度、拒绝计数、幂等冲突率会比论文更早告诉你哪里错了。**地图要同时挂这两种证据。**

### 8.1 把一次线上失败变成一道题和一条断言

<Steps>
<li>复现成确定性输入。撞不到的分支用脚本化的假流复现：不可重复，比不可自动断言更麻烦。</li>
<li>分层。机制层（解析、状态机、计费算术、路径判断）写成零模型断言；agent 行为层（改错位置、空转、改测试）做成 L18 任务集的新题。</li>
<li>新题过 `validateTaskSet`：有 fail-to-pass、钉了 `repoPin`，每个难度层都不为空。gaps 非空，主指标作废。</li>
<li>回到图上。违反了已有不变量，先跑 `blastRadius`，重核完再更新 `evidenceAt`；新不变量就加节点，并至少用一条 `requires` 接上——孤立节点不会出现在任何人的影响面里。</li>
<li>把「故障」改写成「不变量」：一句话，能被违反，能被断言。</li>
</Steps>

这门课自己就走过这条路：L19 调研的探针发现 `bob` 用 `alice` 用过的幂等 key 拿到了她的整份作业（`[O]`），它成了 L19 verify 的租户断言；4.2 那次门禁语义写反，成了今天的 regress / claim 两扇门，也就是 `eval.gate` 的「非劣与优效分两门」。

**故障是图的输入，断言是图的证据。** 中间那一步，是把它说成一句不变量。
